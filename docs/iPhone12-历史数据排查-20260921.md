## 代码核查

- `JournalPersistence` 从现有文档解码，解码失败会报错，不会回退并覆盖为空数据。
- 只有数据库中没有文档时才创建新 Journal。
- 当前业务代码没有删除数据库、清空全部历史的逻辑；跨日只封存未完成计时，不删除历史。
- UI 测试和 TodayView Preview 使用内存数据库；这不能防止 Xcode 在安装 App 的阶段替换数据容器。

## 保全与恢复边界

- 已只读导出真机 `default.store`、`default.store-wal` 和 `default.store-shm`：`TestResults/iPhone12-DataAudit-20260921/original/ApplicationSupport/`。
- 查询在复制出的 working 目录进行；本次没有安装、卸载、启动、停止或回写真机 App，也没有修改业务代码。
- Xcode 启动结果、系统日志、容器清单及解析的 journal.json 保存在同一审计目录，受 TestResults 忽略规则保护。
- 当前副本没有旧记录，不能据此恢复历史。本机 MobileSync/Backup 目录无备份；未检查 iCloud 或其他机器备份。

## 后续防护建议

- 有真实记录的手机避免 Preview on Device；界面预览使用模拟器。
- 若需要长期真机预览，使用独立 Bundle Identifier 的预览应用，使其与真实记录 App 隔离。
- 增加用户可导出的备份；单独保存在同一 App 沙盒内的备份无法防止整个数据容器被替换。
